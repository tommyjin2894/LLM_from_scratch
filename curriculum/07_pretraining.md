### 🍼 유치원 버전

지금까지 우리는 미니 GPT한테 책 한 권(셰익스피어)을 읽혔어.
프런티어 모델은 **도서관 수백만 개 분량(수십조 토큰)**을 읽어.
그러면 세 가지 질문이 생겨:
1. **얼마나 큰 뇌**에 **얼마나 많은 책**을 읽혀야 해? → 스케일링 법칙 (반죽:물 황금비율)
2. 책이 그렇게 많은데 **쓰레기 책**은 어떻게 골라내? → 데이터 파이프라인 (편식 관리)
3. GPU 한 장엔 안 들어가는데? → 분산학습 (코끼리를 냉장고 1000개에 나눠 넣기)

## 🧠 제대로 배우기

### 1. 스케일링 법칙 — LLM 시대를 연 발견
- **Kaplan et al. 2020**: 손실이 모델 크기 N, 데이터 D, 컴퓨트 C의 **멱법칙(power law)**으로 매끈하게 감소. "크게 만들면 좋아진다"가 예측 가능한 과학이 됨 → GPT-3의 근거
- **Chinchilla (2022)**: 같은 컴퓨트면 N과 D를 **같은 비율로** 키워라. 최적은 대략 **D ≈ 20N** (토큰/파라미터). 당시 GPT-3(175B에 0.3T 토큰)는 데이터 부족 상태였음이 드러남
- **Chinchilla 그 후 — 추론 비용의 반격**: 학습은 한 번, 서빙은 영원히. 그래서 작은 모델을 **훨씬 오래**(과잉학습) 훈련하는 게 총비용 최적
  - Llama 3 8B: 15T 토큰 = **~1,875 토큰/파라미터** (Chinchilla의 94배!)
- 컴퓨트 어림식: **C ≈ 6·N·D FLOPs** (왜 6인지 유도해보기 — 순전파 2ND + 역전파 4ND)
- 2024+: "데이터 벽" 논쟁 → 합성 데이터, 다중 에폭, 그리고 **RL/추론으로 축 이동** (Phase 09)

### 2. 데이터 — 사실상 제일 중요한 장
> 프런티어 랩의 진짜 기밀은 아키텍처가 아니라 **데이터 레시피**입니다.

파이프라인 (FineWeb 공개 사례 기준):
1. **수집**: Common Crawl (웹 전체 크롤링 덤프)
2. **추출**: HTML → 본문 텍스트 (trafilatura 등)
3. **언어 필터**: fastText 분류기
4. **품질 필터**: 휴리스틱(문장부호, 반복, 길이) + 모델 기반(교육성 점수 — FineWeb-Edu)
5. **중복 제거**: MinHash LSH (거의 같은 문서 제거 — 암기·오염 방지)
6. **오염 제거**: 벤치마크 문제 유출분 제거 (13에서 재등장)
7. **믹스 설계**: 웹 %, 코드 %, 수학 %, 다국어 % — 코드·수학 비중이 추론력을 끌어올린다는 게 정설
8. **커리큘럼**: 학습 말미에 고품질 데이터 비중↑ (annealing)
- **합성 데이터 시대**: 좋은 모델로 교과서·문제풀이를 생성해 다음 모델 학습 (Phi 계열이 개척, 이제 보편화). 붕괴(model collapse) 논쟁도 같이 알아두기

### 3. 분산학습 — 코끼리 냉장고에 넣기
| 병렬화 | 🍼 비유 | 내용 |
|---|---|---|
| DP (데이터 병렬) | 같은 교과서 복사본 1000권, 반마다 다른 페이지 숙제 | 모델 복제, 배치 분할, 그래디언트 평균 (all-reduce) |
| **FSDP/ZeRO** | 교과서를 찢어 나눠 갖고 필요할 때 모아보기 | 파라미터/그래디언트/옵티마이저 상태 샤딩 |
| TP (텐서 병렬) | 한 문제를 여럿이 나눠 풀기 | 행렬을 쪼개 여러 GPU가 동시에 |
| PP (파이프라인) | 조립 라인 | 층을 GPU별로 나눔, 버블 최소화 |
| EP (전문가 병렬) | 의사들을 병원별로 배치 | MoE 전용 |
- **혼합 정밀도**: BF16이 표준, **FP8 학습**이 최전선 (DeepSeek-V3가 대규모 검증) — 같은 GPU로 2배 빠르게
- gradient checkpointing(활성값 버리고 재계산), gradient accumulation(가난한 자의 큰 배치)
- 학습 안정성 실전: loss spike와 대처(되감기·스킵), z-loss, QK-Norm(06), 그래디언트 클리핑(04)

### 4. MoE — 2026년 표준 아키텍처
- 🍼 *종합병원이야.* 접수처(**라우터**)가 환자(토큰)를 보고 전문의 몇 명에게만 보내.
  의사(전문가 FFN)가 256명 있어도 **진료는 한 번에 8명만** → 지식은 1조 파라미터인데 계산은 30B만큼만
- 구조: FFN을 E개로 복제, 라우터가 토큰별 top-k 선택. 어텐션은 공유
- 핵심 문제 = **부하 균형**: 인기 의사에게만 몰리면 망함 → 보조 손실(aux loss) 또는 DeepSeek의 **aux-loss-free 바이어스 조정**
- 계보: Switch Transformer → Mixtral 8x7B(오픈 첫 히트) → **DeepSeek 미세전문가**(작은 전문가 다수+공유 전문가) → V3 671B/37B → 2026년: DeepSeek V4 1.6T/49B, Kimi K2, Qwen3, Llama 4... **프런티어급은 사실상 전부 MoE**
- **MTP(멀티 토큰 예측)**: 다음 1개가 아니라 2개+를 예측하는 보조 헤드 — 학습 신호 강화 + 추측 디코딩 재료 (DeepSeek-V3)

### 5. 장문맥 학습
- 처음부터 1M으로 학습하면 제곱 비용 폭발 → **단계적 연장**: 4K로 대부분 학습 → RoPE θ 키우고 32K → 128K… 소량 추가 학습
- 평가: needle-in-a-haystack은 너무 쉬워짐 → RULER, 실제 장문 과제로
